# LY工具箱 · 设计方案（v1.0）

> 一句话：**把"手指做不到 / 懒得做"的操作，录成一个快捷键，按一下替你完成。**
>
> 例：上滑下一个视频、停止播放音乐、暂停后返回桌面、打开某个 App。

---

## 1. 产品定位

| 项目 | 内容 |
| --- | --- |
| 名称 | LY工具箱（LY Toolbox） |
| 平台 | Android 7.0（API 24）及以上 |
| 形态 | 常驻工具类 App，无账号、无联网、无广告 |
| 核心价值 | 把高频的重复手势/媒体操作压缩成「一个快捷键 + 一串动作」 |
| 目标用户 | 短视频重度用户、通勤听歌用户、单手操作/行动不便用户、需要自动化的小白用户 |

### 1.1 要解决的具体问题

1. 冬天戴手套 / 手湿 / 单手拿手机时，刷短视频划不动屏幕；
2. 听歌时想立刻静音，要下拉通知栏找播放器，路径太长；
3. 不同 App 的操作位置不一样，用户想要统一的"手势遥控器"；
4. 想做简单自动化（暂停 → 回桌面 → 打开另一个 App），但 Tasker 类工具学习成本太高。

### 1.2 不做什么（边界）

- 不做脚本录制（不采集屏幕内容、不做图像识别）；
- 不做跨设备同步、不联网；
- 不替代启动器，不做桌面美化。

## 2. 核心概念

```
触发器 Trigger  ──绑定──▶  动作序列 [ActionStep, ActionStep, ...]
（怎么按）                  （按了之后依次做什么）
```

- **触发器**：悬浮球的 7 种手势、3 种音量键组合、3 个桌面快捷方式、1 个桌面小组件，共 14 个；
- **绑定（Binding）**：一条"触发器 → 动作序列"的记录，可命名、可启用/禁用；
- **动作（ActionStep）**：最小执行单元，支持执行后延迟（`delayAfterMs`）；
- **动作序列**：按顺序执行，任一动作失败即中止，避免"半套动作"造成误操作。

### 2.1 默认绑定（装上即用）

| 触发器 | 默认动作 |
| --- | --- |
| 悬浮球 · 上滑 | 上滑（下一个视频） |
| 悬浮球 · 下滑 | 下滑（上一个视频） |
| 悬浮球 · 单击 | 播放 / 暂停音乐 |
| 悬浮球 · 双击 | 停止播放音乐 |
| 音量 + 双击 | 上滑（下一个视频） |
| 音量 − 双击 | 停止播放音乐 |
| 桌面快捷方式 1 | 上滑（下一个视频） |
| 桌面快捷方式 2 | 停止播放音乐 |
| 桌面小组件 | 停止播放音乐 |

其余触发器默认无绑定，用户可自行添加。

## 3. 触发方式设计

### 3.1 三种入口的取舍

| 入口 | 优点 | 缺点 | 定位 |
| --- | --- | --- | --- |
| **悬浮球**（主入口） | 全局可用、可见、无需记按键、可拖动避让 | 需要悬浮窗权限；遮挡一小块屏幕 | 日常主用 |
| **音量键组合** | 不占屏幕、盲操、物理反馈 | 系统/ROM 可能吞键；单次按键仍会调音量 | 进阶/备用 |
| **桌面快捷方式 + 小组件** | 稳定、无需常驻 | 必须先回到桌面 | 特定场景（如睡前停止播放） |

结论：**悬浮球做默认主入口**，音量键与桌面入口作为补充；三者共用同一套动作引擎，能力完全一致。

### 3.2 悬浮球手势判定参数

| 手势 | 判定规则 | 参数 |
| --- | --- | --- |
| 单击 | 抬手位移 < 36dp，且 280ms 内无第二次点击 | `TAP_DELAY = 300ms` |
| 双击 | 两次单击间隔 ≤ 280ms | 取消待执行的单击 |
| 长按 | 按住 ≥ 480ms（未移动超过 touchSlop） | 抬手不再触发单击 |
| 上/下/左/右滑 | 抬手位移 > 36dp，取主轴方向 | 阈值 36dp |
| 拖动 | 位移 > 系统 touchSlop 即进入拖动，松手保存坐标 | 位置写入配置 |

> 设计要点：拖动与手势共用一套触摸事件，先判定"是否拖动"，未拖动才进入手势判定，避免拖球时误触发动作。

### 3.3 音量键组合判定

| 组合 | 规则 |
| --- | --- |
| 音量 + 双击 | 两次 `VOLUME_UP` 间隔 ≤ 450ms |
| 音量 − 双击 | 两次 `VOLUME_DOWN` 间隔 ≤ 450ms |
| 双键同按 | 两个音量键按下间隔 ≤ 260ms |

实现方式：无障碍服务开启 `FLAG_REQUEST_FILTER_KEY_EVENTS`，在 `onKeyEvent` 中统计。
**只有识别到组合时才 `return true` 拦截**，单击音量键返回 `false`，正常调音量。

### 3.4 录制流程（用户视角）

```
编辑页 ──点「录制」──▶ 弹窗："请按两次音量+…"
                              │
                     用户按键（弹窗内不改音量）
                              │
              识别成功 ──▶ 自动填入触发方式 + Toast 提示
              识别失败 ──▶ 继续等待 / 取消
```

录制只在**编辑页的弹窗内**进行，避免全局录制带来的误触与权限复杂度；录完即写入该条绑定的触发器。

## 4. 动作库

| 分类 | 动作 | 实现方式 | 依赖 |
| --- | --- | --- | --- |
| 手势 | 上滑 / 下滑 / 左滑 / 右滑 | `dispatchGesture` 画一条路径 | 无障碍 |
| 手势 | 点屏幕中心 | `dispatchGesture` 单点 | 无障碍 |
| 媒体 | 播放/暂停、停止播放、上一首、下一首 | `AudioManager.dispatchMediaKeyEvent` | 无 |
| 系统 | 音量 + / − | `adjustStreamVolume` | 无 |
| 系统 | 返回 / 桌面 / 最近任务 | `performGlobalAction` | 无障碍 |
| App | 打开指定应用（包名） | `getLaunchIntentForPackage` | 可见性声明 |
| App | 打开网页 | `ACTION_VIEW` | 无 |
| 流程 | 等待 N 毫秒 | 协程 `delay` | 无 |

**滑动轨迹**（相对屏幕比例，适配任意分辨率）：

| 动作 | 起点 | 终点 | 时长 |
| --- | --- | --- | --- |
| 上滑 | (50%, 72%) | (50%, 30%) | 260ms |
| 下滑 | (50%, 30%) | (50%, 72%) | 260ms |
| 左滑 | (82%, 50%) | (18%, 50%) | 260ms |
| 右滑 | (18%, 50%) | (82%, 50%) | 260ms |

> 上滑即短视频里的"下一个"，符合抖音/快手/Reels 的通用手势方向。

## 5. Android 能力边界（必须提前说清）

| 能力 | API | 权限 | 限制 |
| --- | --- | --- | --- |
| 模拟滑动/点击 | `AccessibilityService.dispatchGesture`（API 24+） | 无障碍服务 | 用户必须在系统设置里手动开启；部分 ROM 会杀服务 |
| 读/拦按键 | `onKeyEvent` + `FLAG_REQUEST_FILTER_KEY_EVENTS` | 无障碍服务 | 音量键可能被系统层消费；电源键等系统键拿不到 |
| 悬浮窗 | `TYPE_APPLICATION_OVERLAY`（API 26+） | `SYSTEM_ALERT_WINDOW` | 需要用户手动授权；Android 12+ 有后台启动前台服务限制 |
| 全局动作 | `performGlobalAction` | 无障碍服务 | 返回/桌面/最近任务稳定 |
| 媒体控制 | `dispatchMediaKeyEvent` | 无 | 目标 App 需注册 MediaSession |
| 打开其他 App | 显式启动 Intent | `<queries>` 声明 | Android 10+ 后台启动 Activity 受限，前台触发更可靠 |
| 开机自启 | `BOOT_COMPLETED` | `RECEIVE_BOOT_COMPLETED` | 部分 ROM 默认禁止自启 |

**结论**：无解的部分（例如音量键被 ROM 吞掉）不硬刚，用悬浮球兜底，并在 UI 上给出解释。

1. 首页顶部两张状态卡，未授权时显示红色「未开启」+「去开启」；
2. 点「去开启」跳系统无障碍设置 / 悬浮窗授权页；

4. 未授权直接开悬浮球 → 自动弹授权页，不会静默失败。

## 8. 技术架构

### 8.1 分层

```
UI 层        MainActivity / EditBindingActivity
              │  读写配置、展示状态
业务层        ActionRunner（动作编排）
              │  协程串行执行、失败中止
能力层        LyAccessibilityService（手势/全局动作/按键）
             OverlayService（悬浮球前台服务）
             MediaController（媒体键）
             LyWidgetProvider（小组件）
数据层        ConfigStore（SharedPreferences + Gson）
```

### 8.2 类职责

| 类 | 职责 |
| --- | --- |
| `LyApp` | 初始化配置、创建通知渠道 |
| `ConfigStore` | 绑定列表读写、悬浮球开关/坐标、默认绑定 |
| `Trigger` | 14 个触发器的 id / 文案 / 分组（id 持久化，不可随意改） |
| `ActionType` | 动作枚举：文案、是否需要参数、参数提示与默认值 |
| `ActionStep` | 单个动作 + 参数字符串 + 执行后延迟 |
| `Binding` | id、名称、触发器 id、启用状态、动作列表 |
| `LyAccessibilityService` | `dispatchGesture` 滑动/点击、`performGlobalAction`、音量键组合识别 |
| `OverlayService` | 前台服务 + `WindowManager` 悬浮球 + 手势判定 + 位置记忆 |
| `ActionRunner` | 所有入口的统一执行器，协程串行执行动作序列 |
| `MediaController` | 封装媒体按键派发 |
| `LyWidgetProvider` | 1×1 小组件点击 → 执行 `widget` 绑定 |
| `BootReceiver` | 开机按开关状态恢复悬浮球 |

### 8.3 数据模型（JSON）

存储位置：`/data/data/com.ly.toolbox/shared_prefs/ly_toolbox.xml` 中的 `bindings` 字段。

```json
[
  {
    "id": "default_ball_up",
    "name": "下一个视频",
    "trigger": "ball_swipe_up",
    "enabled": true,
    "steps": [
      { "type": "SWIPE_UP", "arg": "", "delayAfterMs": 0 }
    ]
  },
  {
    "id": "6f0c1a7e-....",
    "name": "暂停后回桌面",
    "trigger": "vol_down_double",
    "enabled": true,
    "steps": [
      { "type": "MEDIA_PLAY_PAUSE", "arg": "", "delayAfterMs": 0 },
      { "type": "DELAY", "arg": "200", "delayAfterMs": 0 },
      { "type": "HOME", "arg": "", "delayAfterMs": 0 }
    ]
  }
]
```

约束：

- 同一 `trigger` 只生效**第一条启用**的绑定（`ConfigStore.bindingFor` 取 first）；
- `id` 为空视为新建，保存时生成 UUID；
- 所有字段都有默认值，Gson 反序列化失败时回退到默认绑定，避免白屏。

### 8.4 执行时序

```
用户按悬浮球/音量键/桌面图标
        │
        ▼
ActionRunner.run(trigger)
        │ 读取 binding，检查 enabled / steps
        ▼
CoroutineScope(Main) ── for each step ──▶ perform(step)
        │                                   ├─ 手势 → AccessibilityService.dispatchGesture
        │                                   ├─ 媒体 → dispatchMediaKeyEvent
        │                                   ├─ 系统 → performGlobalAction
        │                                   └─ 参数动作 → Intent / delay
        ▼
   失败即中止 + Toast 提示（同一条提示 1.2s 内去重）
```

- 新的触发会**取消上一条未执行完的序列**，避免两次滑动叠加；
- `delayAfterMs` 与 `DELAY` 动作都是协程挂起，不阻塞主线程。

### 8.5 权限矩阵

| 权限 | 用途 | 授予方式 | 拒绝后果 |
| --- | --- | --- | --- |
| `BIND_ACCESSIBILITY_SERVICE`（服务声明） | 手势、全局动作、按键过滤 | 系统设置手动开启 | 滑动/返回/桌面不可用，媒体键仍可用 |
| `SYSTEM_ALERT_WINDOW` | 悬浮球 | 系统设置手动开启 | 悬浮球不可用，音量键/桌面入口仍可用 |
| `FOREGROUND_SERVICE` + `SPECIAL_USE` | 悬浮球常驻 | 安装即授予 | 无 |
| `POST_NOTIFICATIONS`（API 33+） | 前台服务通知 | 运行时弹窗 | 服务仍运行，通知不显示 |
| `RECEIVE_BOOT_COMPLETED` | 开机恢复 | 安装即授予 | 重启后需手动打开 App |
| `VIBRATE` | 触发震动反馈 | 安装即授予 | 无 |

### 8.6 兼容性与 ROM 适配

| 问题 | 现象 | 对策 |
| --- | --- | --- |
| MIUI/澎湃 | 无障碍服务被"无障碍快捷方式"或省电策略关闭 | 引导加入自启动白名单、锁定后台 |
| EMUI/鸿蒙 | 悬浮窗需在"权限管理 → 悬浮窗"单独开 | 授权页兜底 + 状态检测 |
| ColorOS / OriginOS | 音量键事件不到无障碍服务 | 提示改用悬浮球 |
| Android 12+ | 后台启动前台服务抛异常 | `runCatching` 包裹，回到 App 时自动恢复 |
| Android 13+ | 通知权限被拒 | 不阻塞主流程 |
| Android 14 | 前台服务必须声明类型 | 使用 `specialUse` + `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` |

### 8.7 性能与稳定性

- 常驻只有一个悬浮球 View + 一个前台服务，内存占用 < 30MB，待机耗电可忽略；
- 配置为一整段 JSON（几十条以内），每次触发解析一次，成本可忽略；
- 悬浮球位置、开关状态持久化，进程被杀后重进 App 自动恢复（可选开机恢复）；
- 所有 `WindowManager` 操作 `runCatching`，异常时 `stopSelf`，避免系统级崩溃；
- 无障碍服务断开时 `instance` 置空，动作执行给出明确提示而不是静默失败。

## 9. 隐私与合规

1. **不申请网络权限**，不存在上传通道；动作与配置全部本地。
2. 无障碍服务的用途仅限"执行用户主动触发的动作"，不读取屏幕文本、不监听输入内容；服务描述文案已写明。
3. Google Play 对 `AccessibilityService` 审核严格（尤其"自动化点击"类），建议：
   - 优先侧载 / 国内应用商店分发；
   - 若上架 Play，需在商店页与 App 内提供醒目的用途说明与关闭入口。
4. 上架前补齐：隐私政策、应用图标/截图、`targetSdk` 年度升级。

## 13. 已知限制（写在前面，避免过度承诺）

1. 悬浮球、手势动作必须依赖无障碍服务，用户不开启就只能用媒体键；
2. 音量键组合在部分 ROM 上不可用（系统层拦截），属平台限制；
3. 「音量 + 双击」会占用"快速连按两次调音量"的习惯：第二次按键被识别为快捷键，音量只 +1。习惯连续按音量键的用户，可在首页把该条绑定关掉，或改用悬浮球；
4. 媒体控制依赖目标 App 的 MediaSession，个别播放器不响应；
5. Android 10+ 后台启动第三方 App 可能被拦截，"打开应用"动作在前台触发最可靠；
6. 本工程生成环境没有 Android SDK，**未做真机/模拟器编译验证**，首次构建若报错请以构建日志为准。
